SukiSU 将入口从 `ksu.c` 改为 `ksu_main.c`，拆分了签名回退扫描，并同步上游 KernelSU 的兼容接口和 preinit 代码。两份本地补丁已重新基于该提交生成，补丁文件白名单和审计入口也跟随文件改名调整。

Linux 4.19 继续使用此前的 SELinux 状态备份、假状态页和重启后启用逻辑。新的 SELinux hide 实现保留在 5.10 及以上分支；4.19 的运行时 hook 检查只审计实际使用的旧内核分支。保留 procfs 挂载文件分类修复、CPU spoof 旧字段适配，以及关闭 KPM 时不编译其底层实现的保护。

首次编译发现上游仍包含已不再使用的 `linux/static_call.h`，4.19 无此头文件，因此移除该引用，并将架构头文件路径改为 `include/arch.h`。Makefile 的版本信息改为固定版本号、源码短提交和 builtin 分支名，不再在编译期间查询 GitHub、补全历史或读取远端最新 Release。

旧 Manager 测试针对的单个授权函数已由上游删除。新的宿主测试直接编译内置 Manager 和签名回退的包名到 UID 选择函数，检查内置候选、签名回退候选、未知包、包名前缀、缺少内置候选和空列表，并核对两条扫描路径的证书检查位置。上游拆分扫描后，`ksu_dynamic_manager_verify_apk()` 已没有调用者。本次在签名回退扫描中接回动态 Manager 验证：只有功能已启用、当前 APK 包名能解析、包名与安装列表精确匹配，且注册 UID 与证书验证通过时才授权。补充有效注册、错误证书、错误 UID、跨包复用证书、关闭功能、未知包和包名解析失败的回归用例。

SUSFS 的两个新增提交只修改 README 和通用 KernelSU 集成补丁。对比确认，本项目使用的 `fs/susfs.c`、两份头文件和用户态工具源码未变，继续使用现有 4.19 移植补丁。
